# SpeakPilot TTS 引擎备选评估

状态：规划稿（评估用，不含本机自测数字）
日期：2026-11-21
关联：`docs/SPEAKPILOT-CONVERSATION-PLAN.md` §d 选型表、§f.1 延迟预算、§f.3 六条降级规则

> 本文只做候选梳理与决策标准，**不包含任何本机实测延迟**。本机实测数据由主线的 `speakpilot-latency-harness`（TTS 首包基准）产出，结果回填到 §f.1 延迟预算表，两处不重复、不互相引用估计值。

## 0. 结论先行

- 现有实现只有系统 `AVSpeechSynthesizer`，本机记录的 TTS 首包 **570–820 ms**（见 §f.1，属已有实测记录，不是本文新测），已超出 §f.3「首包 >500 ms 换引擎」的触发线 1.1–1.6 倍。
- 因此"是否换引擎"已经不是假设问题，而是**换哪个**。按可落地性排序：本地小模型（Kokoro / Piper）> 系统引擎参数调优 > 云端流式。
- 但换引擎前必须先有完整实测表（三种候选 × 至少 20 次采样），**没有表不进 P1**，这条门禁不因本文而松动。

## 1. 候选 A：系统 AVSpeechSynthesizer 参数调优

| 维度 | 内容 |
|---|---|
| 接入成本 | 零（已集成），只调参数 |
| 首包延迟 | 已有记录 570–820 ms，未做参数调优后的对照实测【本文不重复测】 |
| 离线 | 是 |
| 许可 | 系统 API，无额外许可成本 |
| 音质/语种 | 中文普通话音色可用，自然度中等；情感与韵律控制弱 |
| 体积 | 0 |

可尝试的调优点：合成器预初始化（常驻实例，避免首次唤醒）、提前构造 `AVSpeechUtterance`、固定 voice 标识避免运行时查找、`rate` 与 `preUtteranceDelay` 归零、避免中途 `stopSpeaking` 再重启。

**判断**：这是唯一零成本的基线，必须先做参数调优再比，否则拿未调优的系统引擎去比别人的最优实现，比出来的结论没有意义。

## 2. 候选 B：本地小模型（含社区 MLX 路线）

| 维度 | Kokoro（82M） | Piper（VITS 系） | XTTS-v2 |
|---|---|---|---|
| 接入成本 | 中（需 sidecar 进程 + 模型分发） | 中（同上，依赖更轻） | 高 |
| 首包延迟 | 未在本机核实；社区报告 Apple Silicon 上可实时【社区实测，未复核】 | CPU 可实时【官方文档：项目 README】 | 未核实，通常更重 |
| 离线 | 是 | 是 | 是 |
| 许可 | Apache-2.0【官方文档：仓库 LICENSE】 | MIT【官方文档】 | CPML，**非商用**，商用需单独授权 |
| 中文 | 支持中文 G2P，音色质量未核实【未核实】 | 有 zh_CN 音色，数量少、质量中等【未核实】 | 支持中文，质量较好但许可受限 |
| 体积 | 模型约百 MB 级【未核实具体量化】 | 更小 | 大（GB 级） |
| 主要风险 | 中文自然度未经听感 A/B；MLX 社区实现的维护活跃度 | 中文音色偏少、机械感 | **许可直接排除商用** |

**判断**：Kokoro 与 Piper 是唯一"离线 + 许可干净 + 体积可控"的组合，其中 Kokoro 质量上限更高、Piper 更稳更轻。XTTS-v2 因许可问题直接排除出商用路径。

## 3. 候选 C：云端流式 TTS

| 维度 | 内容 |
|---|---|
| 接入成本 | 低（HTTP/WebSocket 接口成熟） |
| 首包延迟 | 通常 200–500 ms，强依赖网络与区域【未核实】 |
| 离线 | 否 |
| 许可/成本 | 按字符计费，需 API key 与配额管理 |
| 音质 | 明显优于本地小模型 |
| 体积 | 0 |
| 关键冲突 | **音频要出本机**，与用户"录音只本机处理"的口径冲突；且断网即失效 |

**判断**：只做兜底与对照基线，不作为默认路径。若将来启用，必须在设置里显式提示"音频会上传"。

## 4. 决策标准表

| 触发条件 | 动作 |
|---|---|
| 系统引擎调优后首包仍 >500 ms，且连续 3 轮实测稳定超出 | 进入引擎切换评估（先 Kokoro，后 Piper） |
| 需要完全离线可用 | 排除云端候选 |
| 中文自然度是首要目标 | 优先 Kokoro，用同一批文本做听感 A/B |
| 安装包体积预算敏感（新增 <100 MB） | 优先 Piper，或留在系统引擎 |
| 任一候选在 20 次采样中 P95 >1.0 s | 该候选直接淘汰，不做进一步优化 |
| 候选需要额外授权或非商用许可 | 直接淘汰（XTTS-v2 即属此类） |

## 5. 与 §f.3 降级规则的对齐

- §f.3 的「TTS 首包 >500 ms 换引擎」是**触发条件**，不是结论；换哪个由第 4 节的标准表决定。
- 换引擎属于 P1 前置动作，必须在 Phase 0 实测表完成后进行；Phase 0 期间**只测不改**。
- 若换引擎后仍达不到 L1 区间（1.6–2.2 s），按 §f.3 规则只宣称"对讲机级"，界面不出现"实时对话"字样。

## 6. 待核实清单

1. Kokoro 中文音色自然度的实际听感（需 A/B 样本）
2. Kokoro 社区 MLX 实现在本机的首包与实时系数
3. Piper zh_CN 可用音色清单与质量
4. 云端三家在本地区的首包实际区间与计费口径
5. 各候选模型的实际磁盘体积与是否需要额外运行时依赖

以上五项，Phase 0 的 harness 跑完后应能填掉 2、3 的延迟部分，1、4、5 需要单独补测或查文档。
