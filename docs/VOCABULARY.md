# 词汇表（vocabulary.json）

JustSpeak 的个人词汇表保存在 `userData/vocabulary.json`。它是一个可手改的 JSON
文件，包含三组互不相同的设置。应用里的「词典」页可以直接编辑这三组设置并保存；
需要批量整理时，也可以继续手改这个文件，然后在设置页点「重新加载」。

```json
{
  "terms": ["Kubernetes", "GPT-4o", "张三"],
  "replace": [{ "from": "库贝内特斯", "to": "Kubernetes" }],
  "protect": ["JustSpeak", "FD2008"]
}
```

- **`terms`（解码期术语偏置）**：在模型解码前作为提示传给运行时，希望它更倾向
  于产出这些词。顺序即优先级，越靠前越优先。
- **`replace`（转写后替换）**：模型已经产出文本之后，把 `from` 的写法改成
  `to`。它只能修正「模型确实说成了某个固定错词」的情况。
- **`protect`（保护词）**：这些词不会被替换、归一化或其它规则改写。

术语与替换的区别：`terms` 是给模型的**提示**，可能不起作用；`replace` 是应用
对最终文本的**确定性改写**，一定生效。需要保证的专名建议同时放进 `terms`（争取
模型直接说对）和 `replace`（事后兜底）。

## 限制

- 最多接受 **32 条** `terms`，超出的尾部条目会被忽略。
- 含英文逗号（`,`）的术语会被忽略，因为运行时用逗号分隔术语列表。
- 含控制字符（如 NUL）或 `<|`、`|>` 这类控制 token 字面量的术语会被忽略；
  它们会导致运行时直接失败，因此不会传给模型。

以上忽略都不会阻止听写，也不会影响其它术语。

## 支持矩阵

| 模型 | 解码期术语 | 说明 |
| --- | --- | --- |
| Qwen3-ASR | 生效 | `terms` 作为解码提示传给运行时 |
| SenseVoice | 不生效 | 文本不受影响；结果会带 `VOCABULARY_UNSUPPORTED` 提示 |

设置页会显示术语数量；当当前模型不支持时，会明确提示术语未生效。

## 实测风险

术语偏置是**提示，不是指令**。在本机 Qwen3-0.6B 上实测观察到：

- 一个术语可能让**全部同类词**迁移成同一格式，影响范围远大于该术语本身。
- 术语可能被**回声**进转写结果。
- 也可能让原本正确的词**变得更差**。

因此建议只放少量真正需要的专名，并把 `replace` 作为事后兜底。

应用**绝不做术语的事后改写**：如果模型听错，宁可保留模型原文，也不会为了命中
术语而强行替换文本。

## 起始词表与载入方式

「词典」页提供「载入起始词表（10 词）」。它不是默认值：只有你显式点击时才会
写入 `vocabulary.json`，首次启动不会静默写入任何词条，解码期偏置默认仍为空。
只读清单的唯一真源是仓库里的 `resources/vocabulary-starter.json`。

载入是幂等的：现有术语保持在前面，缺失的起始词按清单顺序追加，已存在的词不会
重复添加。若十个词已全部存在，按钮显示「已全部载入」，并且不会发起写盘。载入与
手工保存走同一条路径：重新规范化（32 条上限、逗号丢弃、非法字符丢弃）、原子
写入、回读校验，界面计数以回读结果为准。

起始词表里的词会进入解码期术语偏置。上文「实测风险」仍然适用：偏置可能迁移同类
词的格式、被回声，或让原本正确的词变差。正式启用前建议先用少量词做 A/B，确认
收益后再长期保留；需要撤销时逐条删除即可。
